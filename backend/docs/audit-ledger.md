# VAANI-RAKSHAK — Cryptographic Audit Ledger & R4 Boundary Specification

## Overview

The Audit Ledger subsystem provides a tamper-evident, strictly ordered, cryptographic SHA-256 hash-chain ledger. It acts as an immutable compliance record for banking risk decisions and establishes a clean integration boundary for future decentralized blockchain anchoring (Hyperledger Fabric) owned by R4.

> **DPDP Act Compliance Rule:**
> **RAW AUDIO AND BASE64 AUDIO ARE NEVER ANCHORED.**
> Only deterministic canonical SHA-256 payload hashes and policy decision summaries are appended to the ledger.

## 2. Canonical Cryptographic Hashing

### 2.1 Payload Hashing
Payloads are canonicalized using deterministic JSON formatting:
```python
canonical_str = json.dumps(payload, sort_keys=True, separators=(",", ":"), default=str)
payload_hash = SHA256(canonical_str)
```

### 2.2 Block Hashing
Every block hash is calculated deterministically over all header and linkage fields:
```python
material = f"{index}:{timestamp}:{block_type}:{call_id or ''}:{segment_id or ''}:{payload_hash}:{prev_hash}:{nonce}"
block_hash = SHA256(material)
```

## 4. REST API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| **`GET`** | `/api/v1/audit/blocks` | Query paginated blocks with optional `callId` and `blockType` filters |
| **`GET`** | `/api/v1/audit/blocks/{block_index}` | Retrieve single block by monotonic index |
| **`GET`** | `/api/v1/audit/calls/{call_id}` | Retrieve complete immutable audit trail for a call |
| **`GET`** | `/api/v1/audit/verify` | Verify cryptographic SHA-256 chain integrity and detect tampering |
| **`GET`** | `/api/v1/audit/proof/{call_id}` | Export cryptographic proof bundle for R4 blockchain anchoring |
